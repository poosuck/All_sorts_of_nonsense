## 원본 비교

- 원본 TS와 생성 JS에 동일한 충격·잡기·복원을 1,000 step 적용했고, 물성 채널 및 변형 정점이 정확히 일치했습니다.
- 손·양푼·채찍 타격·채찍 휘두르기 4개 MP3의 바이트가 제공된 TS 데이터와 같습니다. 검토용 MP3 사본도 대조했습니다.
- 원본 레이아웃·문구·상태별 안내·도구 그림·5가지 맛·기본값 60/50을 Vue에 연결했습니다. 추가한 홈 복귀와 볼륨 때문에 패널 높이는 달라집니다. 픽셀 단위 완전 일치는 주장하지 않습니다.
- 원본의 손/양푼 6, 휘두르기 3, 채찍 충격 1 voice 정책을 보존했습니다. 채찍 줄·재타격 latch·공기 파동 코드는 원본 모듈입니다.

## 브라우저에서 실제로 확인한 동작

- 별짓 홈·기획 중 카드·독립 푸딩 페이지·404.
- `/pudding` 직접 접근·새로고침·홈 링크 복귀.
- WebGL 렌더링, 누르기·당기기 시 화면 변화, 놓은 뒤 원래 상태로 복원.
- 손·양푼의 실제 포인터 스윕 타격, 빗나감과 우클릭 배제.
- 채찍 줄의 실제 접촉과 overlay 해제.
- 5가지 맛·선택 저장·물성 슬라이더·원본 리셋·키보드 타격.
- 390px 모바일의 가로 넘침·터치 누르기/해제.
- 실제 AudioWorklet 샘플 출력, voice 중첩, 볼륨 0/재개, 음소거/해제, 페이지 이탈 시 AudioContext 닫힘.
- 검사 중 수집한 페이지 예외와 error 콘솔은 없었습니다.

실제 마우스 휘두르기에서도 손 32.4ms, 양푼 27.7ms의 입력 이벤트 → source 스케줄링 시간을 기록했습니다. 재생 offset은 원본의 0.2초/0.05초와 일치했습니다. [측정 기록](pointer-audio-check.json)

오디오 검사에서 키 입력부터 source 스케줄링까지 150ms 미만, 빠른 연속 source 스케줄 간격 20ms 미만을 확인했습니다. 짧은 음원이 끝나 측정에서 사라지지 않도록 오디오 스레드의 샘플을 수집했습니다. 이는 스피커·운영체제의 최종 출력 지연이나 사람의 청감 평가를 의미하지 않습니다.

브라우저 환경: Chromium 154, headless SwiftShader. 반복 통합 검사에는 deviceScaleFactor 0.5를 사용했고, PNG 검토 화면은 1로 별도 캡처했습니다. 실 GPU·브라우저 폰트에 따른 화면 차이가 있을 수 있습니다.

검토용 화면: [홈](screenshots/home-desktop.png), [푸딩](screenshots/pudding-desktop.png), [모바일 홈](screenshots/home-mobile.png). 모바일 푸딩은 터치·뷰포트·overflow 동작을 통합 검사로 검증했으며, headless 캡처에서 포인터 미디어 조건과 그림이 일치하지 않아 해당 PNG는 검토 자료에서 제외했습니다.

## 남은 검토·배포 범위

- 실제 스피커의 음색·음량·체감 타격감, 실기기 Safari/Firefox.
- 브랜드 정의서 v0.7 전문의 요약 밖 세부 규정(전문 미제공).
- GitHub 업로드 결과 확인. 저장소 생성·이름 변경은 진행하지 않습니다.
- 별도 승인 후 Netlify 배포와 직접 URL 및 기기 검사.
- 클라우드 환경 설정 초안의 사용자 검토·저장·환경 게시, 새 작업에서의 복원 검증.

Three.js와 원본 내장 음원이 포함된 지연 로딩 청크는 압축 전 약 699 kB, gzip 약 234 kB입니다. Vite의 500 kB 크기 경고가 있지만 빌드 오류는 아닙니다. 홈에서는 이 엔진을 로드하지 않습니다.

2026-10-23 검증 시점에는 GitHub·Netlify·기존 Sites에 쓰기/게시 작업을 하지 않았습니다. 2026-10-24 사용자 지시에 따라 GitHub 업로드 대상은 `poosuck/All_sorts_of_nonsense`로 확정하고 Netlify 배포는 보류합니다. 프로젝트/package 이름 `byeoljit`은 유지합니다. 기존 작업의 이전 사본과 업로드 ZIP은 작업 공간에 별도로 보존했습니다.

채팅에서 보고된 ‘시각화 내부에서 오류 발생’은 사용자가 채팅 미리보기 영역의 메시지라고 확인했습니다. 그 렌더러의 원인은 확인하지 못했으며 웹앱 런타임 오류로 분류하지 않았습니다. 검토 화면은 독립 PNG 파일로 제공합니다.
