# 별짓 — 비둘기 모이주기 기능 명세서 v1.0

작성일: 2026-10-24  
대상: 콘텐츠 002 · PC 웹  
상태: 기획 명세. 구현 및 게시 완료를 의미하지 않음.

## 1. 목적과 문서 기준

모이를 던지면 비둘기가 몰려들어 먹고, 서로 싸우거나 사랑에 빠지며, 배부르면 떠나는 웹 놀이터다. 사용자는 모이의 위치와 비둘기 접촉을 통해 상황에 개입하고 예상하지 못한 반응을 관찰한다.

- **확정**: 사용자가 직접 선택하거나 수정한 요구사항.
- **설계안**: 확정 요구사항을 구현하기 위한 구체적인 처리 방식. 승인된 사실과 구분한다.
- **조정값**: 실제 플레이로 조정할 초기 수치. 출시 확정 수치가 아니다.

## 2. 시각 기준 — 확정

선택 시안: A+ · 3D 장난감 + 사실적인 눈. 첨부된 793fd8db-c317-4853-b00b-9dedf2677111.png를 기준으로 한다.

- 따뜻한 햇살이 비치는 한국 공원, 포장 바닥, 벤치와 녹지.
- 통통한 3D 비둘기, 부드러운 깃털 표현, 작은 주황빛 홍채와 검은 동공.
- 닭둘기는 일반 비둘기보다 과장되게 둥글고 커다란 체형.
- 몸의 무게감, 고개 움직임, 날갯짓, 뒤뚱거림을 핵심 품질 요소로 취급.
- 시안의 도감 초상화 수, 글자 배치, 궤적 방향은 기능 확정 사항이 아니며 아래 명세에 따라 정리한다.
- 생성 시안은 목표 분위기와 형태의 참고 자료다. 실제 움직이는 모델·애니메이션·배경 자산 제작은 별도 작업이다.

## 4. 기본 플레이 흐름 — 설계안

접속 → 도감 불러오기 → 비둘기 방문 → 모이 조준·투척 → 먹기·접촉·사건 발생 → 성장 또는 퇴장 → 새로운 비둘기 방문.

별도의 승패나 강제 종료 없이 반복한다. 로그인 없이 바로 시작하고, 초기에는 현재 브라우저에 도감을 저장하는 구성을 제안한다. 계정 동기화는 미정이다.

## 5. 입력과 모이 던지기

### 5.1 입력 구분 — 설계안

- 짧게 클릭 후 놓기: 비둘기가 있으면 한 번 툭 밀기. 빈 바닥에서는 행동 없음.
- 누른 채 일정 거리 이동: 던지기 조준으로 전환. 이후 클릭 반응을 발생시키지 않는다.
- 길게 누른 채 이동하지 않기: 별도 행동 없음. 놓을 때에도 뒤늦은 툭 치기 없음.
- 조준 중 놓기: 모이 한 회분 소비 및 발사.
- UI 위에서 시작한 입력: 도감·음소거 등 해당 UI만 작동.
- 화면 이탈, 포커스 상실, 입력 취소: 조준 취소, 모이 소비 없음.

조준은 아래쪽 투척 지점에서 시작하는 고정 시점 방식으로 제안한다. 드래그 방향으로 던지고 드래그 길이로 거리를 정한다. 조준 중 예상 궤적과 착지 영역을 표시한다. 시안의 곡선 화살표는 이 규칙에 맞게 수정한다.

### 5.2 모이 자원 — 확정 및 설계안

자동 충전은 확정이다. 회분 단위 저장, 최대 보유량, 충전 막대는 설계안이다. 한 회분에서 여러 알이 퍼져 나온다. 조준만으로 소비하지 않으며, 부족하면 충전 상태를 보여준다. 탭이 비활성화되면 시뮬레이션과 충전 시간을 함께 정지하는 방식을 제안한다.

### 5.3 모이 충돌과 부착

바닥에 닿으면 짧게 튀고 정착한다. 비둘기에 닿으면 일부는 충돌 부위에 붙고 나머지는 떨어진다. 부착 여부는 충돌 시 한 번 판정한다.

부착된 모이는 몸통·머리·날개 등 맞은 부위의 움직임을 따라가야 한다. 비둘기가 돌아서거나 밀려나도 공중에 남거나 몸 안으로 깊게 파고들지 않아야 한다. 먹힌 모이는 즉시 제거하며, 같은 알을 두 마리가 중복 섭취할 수 없다.

설계안: 부착 개수와 존속 시간을 제한하고, 초과 모이는 바닥으로 떨어뜨린다. 다른 비둘기가 실제 접근 가능한 위치의 모이만 먹게 한다. 퇴장한 개체에 붙은 모이는 함께 정리한다. 붙었다는 사실만으로 포만감은 증가하지 않는다.

## 6. 비둘기 생애와 닭둘기

### 6.1 방문과 식사 — 설계안

비둘기는 화면 가장자리에서 걷거나 날아 들어온다. 주변 모이를 찾고 접근해 쪼아 먹는다. 목표 모이가 사라지면 다른 알을 찾는다. 목표 개체 수보다 적어지면 간격을 두고 새 비둘기를 방문시킨다.

### 6.2 성장과 퇴장

식사량에 따라 체형이 점진적으로 둥글어지는 표현을 사용한다. 닭둘기 성장과 배부른 퇴장이 충돌하지 않도록 다음 처리를 제안한다.

- 일반 비둘기 일부를 성장 가능한 개체로 설정한다.
- 성장 조건을 채웠고 닭둘기 자리가 있으면 변신한다.
- 변신 시 포만도 기준을 닭둘기 단계로 전환해 즉시 퇴장하지 않게 한다.
- 성장하지 않은 개체는 일반 포만도 기준에서 퇴장한다.
- 배부른 비둘기는 새로운 먹이 추적을 멈추고 퇴장한다.
- 날아서 떠나기와 걸어서 떠나기를 모두 제공한다. 닭둘기는 걸어서 떠나는 비중을 높이는 연출을 제안한다.

### 6.3 두 마리 제한

방문 닭둘기와 성장 닭둘기를 합쳐 화면에 최대 두 마리만 허용한다. 퇴장 애니메이션 중인 닭둘기도 화면에서 완전히 나가기 전까지 센다.

설계안: 자리가 없으면 추가 닭둘기 방문을 보류하고 성장을 막는다. 일반 비둘기의 식사와 퇴장은 계속한다. 같은 순간에 방문과 성장이 겹쳐도 먼저 자리를 확보한 개체만 허용한다.

## 7. 직접 접촉과 성격

클릭 시 비둘기를 옆으로 밀고 다음 반응 중 하나를 재생한다.

| 반응 | 확정 여부 | 연출 |
|---|---|---|
| 무시 | 확정 | 밀린 위치에서 먹기 등 기존 행동을 계속한다. |
| 격한 반격 | 확정 | 펄쩍 뛰거나 날개를 펼치며 사용자 쪽으로 덤비려 한다. |
| 소심한 회피 | 설계안 | 짧게 피한 뒤 주변을 살피고 돌아온다. |
| 뻔뻔한 응시 | 설계안 | 잠깐 쳐다보고 다시 먹는다. |

성격을 개체별로 유지하되 반응에 약간의 무작위성을 주는 방식을 제안한다. 반격은 커서 방향으로 다가가 쪼려는 연출이며 게임오버는 없다. 연속 클릭으로 화면 밖으로 튕겨 나가거나 반응이 무한 중첩되지 않도록 이동량과 반응 빈도를 제한한다.

## 8. 개체 간 사건

### 8.1 몸 충돌과 싸움

몸이 닿았을 때 싸움 여부를 판정한다. 매 프레임 판정하지 않고 새로운 접촉이 시작될 때 한 번 판정하는 설계다. 싸움은 두 개체가 서로 바라보고 가슴을 내밀거나 날개를 퍼덕이며 밀치는 형태로 표현한다.

설계안: 짧은 시간이 지나면 한쪽이 물러나고 둘 다 일상으로 복귀한다. 사건 이후 재발 대기 시간을 둔다. 한 개체가 여러 싸움에 동시에 참여하지 않는다.

### 8.2 싸우는 비둘기에게 모이 던지기

싸우는 두 개체 주변에 새로 던진 모이가 도달하면 한 번만 반응을 선택한다.

| 분기 | 행동 | 이후 처리 — 설계안 |
|---|---|---|
| 눈총 | 둘 다 싸움을 잠깐 멈추고 사용자 쪽을 째려본다. | 짧게 응시한 뒤 남은 싸움을 마치거나 일상 복귀. |
| 화해와 식사 | 싸움을 끝내고 떨어진 모이를 함께 먹는다. | 재발 대기 시간을 적용해 즉시 다시 싸우지 않게 한다. |

한 투척의 여러 알이 동일 싸움을 반복 발동시키지 않는다. 몸에 맞은 모이는 이 사건과 별개로 부착 규칙을 적용한다.

### 8.3 몸에 붙은 모이 먹기

다른 개체가 접근 → 부착된 알을 쪼아 먹음 → 먹힌 개체의 반응 판정 → 무시 또는 싸움.

먹은 알은 먹은 개체의 포만도에만 더한다. 모이가 있던 개체는 포만도가 증가하지 않는다. 먹기 동작 한 번마다 판정하며, 새 싸움은 두 개체가 모두 다른 사건에 참여하지 않을 때만 시작한다.

### 8.4 첫눈에 반함과 데이트

두 비둘기가 서로를 바라봄 → 접근과 호감 동작 → 나란히 화면 밖으로 이동. 두 개체 모두 퇴장 처리한다.

설계안: 싸움·퇴장 중인 개체는 연애를 시작하지 않는다. 연애가 성립한 뒤에는 모이 추적을 중단하고 짝을 유지한다. 데이트 중 클릭하면 짧게 밀린 후 함께 이동을 재개하며, 새 싸움을 중복 생성하지 않는다.

## 9. 상태와 사건 충돌 처리 — 설계안

개체의 주요 상태: 입장, 배회, 모이 접근, 먹기, 접촉 반응, 싸움, 사용자 응시, 구애, 데이트 퇴장, 배부른 퇴장.

- 한 개체는 한 번에 하나의 주요 상태와 최대 하나의 관계 사건만 가진다.
- 싸움 중 포만 기준에 도달하면 현재 짧은 반응을 마치고 퇴장한다.
- 연애와 싸움 조건이 동시에 충족되면 먼저 성립한 사건만 유지한다.
- 대상이 퇴장하거나 사라지면 추적·싸움·부착 모이 먹기 참조를 즉시 해제한다.
- 모이 화해가 성립하면 싸움 예약을 취소한다.
- 클릭에 의한 순간적인 밀림은 현재 사건의 참여자 정보를 파괴하지 않는다.
- 몸 부착 모이, 바닥 모이, 사건 로그는 개체 제거 시 누락 없이 정리한다.

## 10. 번호와 사건 알림

확정: 사건 문구에는 비둘기와 번호를 조합한 이름만 사용한다. 닭둘기도 사건에서는 비둘기X로 부른다.

설계안: 접속 세션마다 1번부터 방문 순서대로 부여하고, 떠난 번호를 재사용하지 않는다. 성장해도 번호는 같다. 화면에서 해당 개체를 찾도록 사건 발생 시 짧게 번호를 표시하며, 평소에는 마우스를 올리면 확인할 수 있게 한다.

| 사건 | 문구 예시 |
|---|---|
| 싸움 | 비둘기1과 비둘기4 사이에 싸움이 붙었습니다. |
| 눈총 | 비둘기1과 비둘기4가 당신을 째려봅니다. |
| 화해 | 비둘기1과 비둘기4가 싸움을 멈추고 모이를 먹습니다. |
| 부착 모이 | 비둘기3이 비둘기6의 몸에 붙은 모이를 먹습니다. |
| 부착 모이 시비 | 비둘기6이 발끈해 비둘기3과 싸움이 붙었습니다. |
| 호감 | 비둘기2와 비둘기7이 서로에게 반했습니다. |
| 데이트 | 비둘기2와 비둘기7이 데이트하러 떠났습니다. |
| 성장 | 비둘기3이 닭둘기가 되었습니다. |
| 반격 | 비둘기5가 당신에게 덤벼듭니다. |
| 퇴장 | 비둘기6이 배불러서 떠났습니다. |

모든 사건은 일관된 번호 체계를 사용한다. 다만 모이 한 알마다 알림을 띄우지 않도록 같은 개체의 반복 섭취 사건은 묶는 설계를 제안한다. 화면에는 최근 알림만 표시하고 펼치면 세션 기록을 볼 수 있게 한다.

## 11. 도감과 저장

확정: 도감만 영구 저장한다. 현재 개체, 살찐 정도, 포만감, 관계, 바닥·부착 모이, 사건 진행 상황은 저장하지 않는다.

설계안:
- 처음 등장하거나 성장으로 발견한 종류를 즉시 도감에 등록한다.
- 닭둘기는 방문과 성장 어느 경로로 발견해도 같은 종류로 등록한다.
- 도감 항목: 종류 ID, 이름, 대표 이미지, 짧은 설명, 발견 여부.
- 개체 번호는 도감 이름으로 쓰지 않는다.
- 저장 구조에 버전을 두고, 도감 종류 추가 시 기존 발견 기록을 유지한다.
- 브라우저 저장 실패 시 플레이는 계속하고 저장 불가 안내를 한 번 표시한다.
- 사이트 데이터 삭제나 다른 브라우저에서는 기록이 유지되지 않는다는 점을 도감 안내에 짧게 표시한다.

초기 종류 수와 목록은 미정이다. 일반 비둘기와 닭둘기 외 종류는 별도 디자인 후 추가한다.

## 12. 화면·사운드·품질 — 설계안

| 영역 | 내용 |
|---|---|
| 중앙 | 공원과 비둘기, 모이 및 사건 연출 |
| 상단 | 콘텐츠 제목, 별짓 홈 이동, 음소거 |
| 하단 | 모이 잔량·충전 상태, 간단한 조작 안내 |
| 한쪽 모서리 | 사건 알림과 기록 펼치기 |
| 도감 버튼 | 발견한 종류와 미발견 항목 확인 |

UI가 투척 입력을 가로채지 않도록 영역을 분리한다. 드래그 중 글자 선택이나 페이지 스크롤을 방지한다. 모이 소진 상태는 색뿐 아니라 수치·아이콘으로도 알린다.

효과음 후보: 모이 흩어짐, 바닥·몸 충돌, 쪼기, 구구 소리, 날갯짓, 싸움, 퇴장. 동시에 울려도 기존 소리를 매번 끊지 않되 동시 재생 수를 제한한다. 자동 재생 제한을 고려해 첫 사용자 입력 이후 사운드를 시작한다.

성능 목표는 기준 PC와 브라우저를 정한 뒤 확정한다. 설계 목표는 최대 개체·모이 상태에서도 부드러운 조작이며, 개체/모이 상한, 화면 밖 객체 제거, 탭 비활성 시 일시정지를 적용한다. 카메라 시점 변경과 모바일 터치는 후속 범위다.

## 14. 구현 검수 기준

1. 드래그로 던진 뒤 클릭 반응이 중복 발생하지 않는다.
2. 길게 누르기로 쓰다듬기나 뒤늦은 클릭이 발생하지 않는다.
3. 모이는 투척 성공 때만 소비되고 최대 보유량까지만 충전된다.
4. 배부른 개체는 비행 또는 걷기 연출로 완전히 퇴장한다.
5. 방문과 성장이 동시에 발생해도 닭둘기가 두 마리를 넘지 않는다.
6. 무시 반응과 격한 반격 반응을 각각 재현할 수 있다.
7. 몸 충돌 싸움, 연애, 데이트 동반 퇴장이 동작한다.
8. 싸움에 모이를 던졌을 때 눈총과 화해 양쪽 분기를 재현할 수 있다.
9. 몸에 붙은 모이가 회전·이동·날갯짓 중 타격 부위를 따라간다.
10. 부착 모이를 먹으면 해당 알이 한 번만 제거되고 먹은 개체만 포만도가 증가한다.
11. 부착 모이 섭취에서 무시와 싸움 양쪽 분기를 재현할 수 있다.
12. 사건 참여자는 한 사건에만 속하고 대상 퇴장 시 오류가 남지 않는다.
13. 모든 사건의 번호가 실제 참여 개체와 일치하며 성장해도 유지된다.
14. 새로고침 후 도감은 유지되며 개체·모이·사건은 초기화된다.
15. UI 조작 중 투척·타격이 발생하지 않는다.
16. 최대 개체와 모이 상태로 장시간 실행해도 객체·로그·음성이 무한 증가하지 않는다.

무작위 분기는 개발용 강제 발생 기능으로 각각 검수한다. 자연 플레이에서는 사건 빈도, 충전 대기, 같은 사건의 반복 피로도를 추가 확인한다.

## 15. 개발 순서와 남은 결정

1단계: 선택 시안에 맞춘 비둘기·공원 자산과 걷기·먹기·날기 검증.  
2단계: 투척, 충전, 기본 식사, 성장, 퇴장, 닭둘기 상한.  
3단계: 클릭 반응, 충돌 싸움, 화해·눈총, 연애.  
4단계: 부위별 모이 부착과 다른 개체의 섭취·시비.  
5단계: 도감 저장, 사건 알림, 사운드, 성능·입력 검수.

남은 결정은 초기 도감 종류, 모이 충전·행동 확률의 최종값, 배경음악 여부, 실제 3D 자산 제작 방식 및 지원 PC 사양이다. 본 문서의 설계안과 조정값은 구현 출발점이며 사용자 확정 요구사항을 대체하지 않는다.
