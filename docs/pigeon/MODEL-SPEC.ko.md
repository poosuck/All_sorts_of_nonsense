# 비둘기 새 모델 제작·웹 렌더링 명세서 v1.0

작성일: 2026-10-29

대상: 별짓 콘텐츠 002 · 일반 회색 비둘기 1개체 · PC 웹

상태: 제작 명세. 모델 제작·도구 도입·렌더링 품질 검증이 완료됐다는 뜻은 아니다.

## 1. 목적과 적용 범위

사용자가 새로 제공한 **8방향·얼굴 확대·다양한 자세가 포함된 비둘기 시트**를 기준으로, 수정 가능한 3D 원본과 웹에서 동일한 외형을 보여 주는 GLB 모델을 제작한다.

핵심 품질은 둥글지만 부위가 구분되는 체형, 몸통에서 자연스럽게 이어지는 날개, 방향과 층이 읽히는 깃털, 섬세한 얼굴이다. 우선순위는 **체형 → 날개 연결·겹깃 → 몸통·목 깃털 → 색·재질 → 기본 자세 → 웹 최적화**다. 조명은 비교가 가능한 중립광으로 고정하며 최종 분위기 연출은 후순위다.

### 1.1 요구사항의 구분

- **요구사항**: 사용자가 지정한 목표와 이번 명세에서 구체화한 제작·검증 조건.
- **초기 설계값**: 구현을 시작하기 위한 제안값. 이미지 실측값이나 달성한 성능으로 설명하지 않는다.
- **도입 후보**: 문서·소스를 조사한 도구. 실행·호환성 검증 후 채택 여부를 기록한다.

### 1.2 1차 범위

| 포함 | 산출·확인 내용 |
|---|---|
| 일반 회색 비둘기 1종 | 동일한 본체·날개·재질·리그를 모든 시점과 자세에서 사용 |
| 외형 제작 | 몸통·목·머리·날개·꼬리·눈·부리·발과 부위별 깃털 |
| 8방향 검증 | 정면, 좌측 45°, 좌측면, 후면 좌측 45°, 후면, 후면 우측 45°, 우측면, 우측 45° |
| 확대 검증 | 얼굴 정면·측면, 목 깃털, 날개 뿌리와 겹깃, 발 |
| 기본 자세 7종 | 서기, 한 발 들기, 먹기, 고개 돌리기, 날개 펼치기, 앉기, 눈 감기 |
| 웹 연결 | `/pigeon`에서 모델 관찰, 시점·자세 전환, 초기화 |
| 제작 기록 | 원본·배포 모델 버전, 검증 캡처, 비교 결과와 남은 차이 |

연속 걷기·쪼기·날갯짓, 이륙·착지 이동 애니메이션, 다중 개체, 닭둘기·성장·체형 슬라이더, 공원 배경, 모이·싸움·도감·음향은 후속 범위다. 1차의 한 발 들기와 날개 펼치기는 리그를 검증하는 **정지 자세**이며, 연속 동작 구현 완료로 표시하지 않는다.

## 2. 기준 이미지와 우선순위

### 2.1 기준 시트 R01

R01은 이번 명세 요청에 앞서 사용자가 제공한 새 시트다. 이미지 파일 자체는 현재 저장소에 등록되어 있지 않다. 아래 ID는 대화 이미지의 구역을 식별하기 위한 것이며, 실제 파일이 존재한다는 뜻은 아니다.

| ID | 시트의 구역 | 사용 목적 |
|---|---|---|
| R01-ROT-01~08 | 상단 기본 8방향 | 체형·머리·접힌 날개·꼬리의 일관성 |
| R01-FACE-01~02 | 오른쪽 상단 얼굴 정면·측면 확대 | 눈·눈테·납막·부리·짧은 머리 깃 |
| R01-POSE-01~07 | 가운데 서기·걷기·먹기·경계·날개 펼치기·앉기·휴식 | 관절, 부위 변형, 자세의 무게감 |
| R01-CAM-01~06 | 하단 로우 앵글·후면·착지·하이 앵글·군집 속 구도 | 배·날개 아래·등·꼬리·가려진 부위의 보조 확인 |

구현에 사용할 때 접근 가능한 원본 시트를 보존하고, 각 구역을 무손실로 분할한 뒤 위 ID와 연결한다. 파일명·해상도·체크섬·분할 영역을 기록한다. 확대나 재생성한 이미지는 원본과 구분한다.

### 2.2 기준의 적용 규칙

1. 기본 체형은 R01의 서 있는 정면·측면·후면을 우선한다. 먹기·앉기는 같은 몸의 자세 변화로 구현한다.
2. 시트가 정확한 정투영 도면이라고 가정하지 않는다. 시점별 크기·원근 차이를 정리하고 공통 비율을 정한다.
3. 좌우 시점의 차이가 하나의 모델에서 양립하지 않으면 기본 3방향과 부위 확대를 우선하고 차이를 기록한다. 시점마다 모델을 바꿔 맞추지 않는다.
4. 이전 먹이 먹는 회색 비둘기 사진은 자세·겹깃의 보조 자료로만 사용한다. 새 시트와 충돌하면 R01을 따른다.
5. 기존 실사 모델, 흰 비둘기 시안, 닭둘기는 새 모델의 체형·색·재질 기준으로 혼합하지 않는다.
6. [원본 게임 기능 명세](pigeon_feeding_spec_v1.0.md)는 후속 기능의 참고 자료다. 이번 외형·제작 범위는 이 문서가 우선한다.

## 3. 제작 도구와 원본 관리

### 3.1 제작 경로

**Blender 원본 → 메시·재질·리그·포즈 정리 → GLB 내보내기 → 현재 Vue·Three.js 프로젝트에서 검증**한다.

- 몸체·날개·깃털의 형상 수정은 Blender 원본에 반영하고 다시 내보낸다.
- 동일한 모델의 외형을 Blender와 웹 양쪽에서 대조한다. 웹에서만 별도의 몸체를 생성해 대체하지 않는다.
- Geometry Nodes, 인스턴스, 제약, 드라이버, 커스텀 셰이더는 GLB에 그대로 보존된다고 가정하지 않는다. 필요한 형상은 메시로 확정하고, 자세는 내보낼 수 있는 본·스킨·모프 또는 베이크된 데이터로 변환한다.
- 삭제한 이전 모델을 다시 기본 모델로 연결하지 않는다. 현재 모델이 없거나 손상되면 재시도 가능한 오류를 표시한다.

기본 경로는 Blender에서 직접 조형·수정하는 방식이다. 자동 생성 도구의 GPU 환경이 없어도 이 경로로 진행할 수 있다. 자동 생성 초안은 체형·날개 분리·발·얼굴·리그 검증을 거쳐 사용한다. 시트 전체를 한 장의 물체 입력으로 넣지 않으며, 동시 입력에는 같은 서 있는 자세의 시점을 사용한다.

도입 시 저장소 URL, 실제 사용 커밋, 라이선스, 사용 파일과 수정 내역, Blender·내보내기 도구 버전을 기록한다. 위 링크는 조사 출처이며 채택한 버전이 확정됐다는 의미는 아니다.

### 3.3 자산 관리 설계

아래 경로는 향후 구현용 설계이며 이번 문서 작성으로 모델 파일이 생성된 것은 아니다.

```text
art/pigeon/pigeon.blend                     # 수정 가능한 원본
art/pigeon/textures/                        # 원본 텍스처·베이크 결과
src/assets/pigeon/pigeon.glb                # 런타임에서 사용하는 단일 모델
src/assets/pigeon/manifest.json             # 원본/GLB 해시·버전·도구·재질·포즈 정보
src/features/pigeon/                       # 향후 로더·관찰 장면·자세 선택 코드
docs/pigeon/reviews/<revision>/             # 실제 캡처와 비교 기록
```

큰 원본은 저장소 용량을 확인해 Git LFS 등 보관 방식을 정하고 문서에 실제 위치를 남긴다. 배포 GLB의 파일명·번들 해시와 원본 버전을 연결한다. 과거 자산을 런타임에서 번갈아 선택하는 분기는 만들지 않는다.

## 4. 비율·좌표·카메라 규칙

### 4.1 공통 비율 측정

기본 서기에서 바닥부터 정수리까지 높이를 **H=1**로 정규화한다. 이는 측정용 비율이며 실제 비둘기의 높이가 1m라는 뜻은 아니다. 부리 끝부터 꼬리 끝까지 길이를 L, 정면 몸통 최대 폭을 W로 기록한다.

| 측정 항목 | 기록·검증 방법 |
|---|---|
| 체형 | L/H, W/H, 몸통 앞뒤 길이, 가슴의 최대 돌출 위치, 배의 최저점 |
| 머리·목 | 머리 폭·높이/H, 눈 중심 높이/H, 머리와 가슴 사이 노출 목 길이, 목 뿌리 폭 |
| 날개·꼬리 | 날개 뿌리 위치, 접힌 날개 길이·두께, 깃 끝과 꼬리 끝의 관계 |
| 얼굴 | 눈 지름/머리 폭, 눈과 부리 간 거리, 부리 길이·각도, 납막 크기 |
| 발 | 배 아래 노출 다리 길이, 양발 간격, 발가락 길이·접지점 |

1단계에서 R01의 정면·측면·후면을 같은 높이로 맞춰 위 비율을 측정하고 작업 기준표를 만든다. 측정 전의 임의 숫자를 이미지 실측값으로 고정하지 않는다. 원근·포즈 때문에 하나의 값으로 정하기 어려운 항목은 범위와 근거를 남긴다.

### 4.2 좌표와 시점

- Blender 기준: +Z 위, 개체의 정면 -Y, 개체의 왼쪽 +X. 원점은 기본 자세 양발 사이의 바닥점이다.
- 좌우 표기는 화면이 아니라 **개체 기준**이다. 정면 0°에서 개체 왼쪽 방향으로 카메라를 이동해 45° 간격의 8방향을 만든다.
- 순서: 정면 → 좌측 45° → 좌측면 → 후면 좌측 45° → 후면 → 후면 우측 45° → 우측면 → 우측 45°.
- 8방향 캡처는 모델·서기 자세·카메라 높이·거리·렌즈·광원을 유지하고 방위만 바꾼다. 발과 꼬리까지 프레임에 포함한다.
- 기본 체형 비교는 같은 크기의 정투영 캡처를 사용한다. R01의 원근이 강한 구도는 별도의 원근 카메라로 보조 비교하며 두 방식을 구분한다.
- GLB의 위쪽 축 변환은 내보내기에서 정리한다. 재가져오기와 웹에서 앞·뒤·좌·우, 노멀, 스킨 변형이 일치하는지 확인한다.

## 5. 부위별 형상 요구사항

| ID | 부위 | 제작 요구사항 | 확인 방법 |
|---|---|---|---|
| GEO-01 | 전체 체형 | 등에서 꼬리로 흐르는 방향, 넓은 가슴과 낮고 둥근 배를 함께 유지. 머리·목·가슴의 부위 차이가 읽혀야 함 | 정면·측면·후면 무채색 비교 |
| GEO-02 | 몸통·목 | 가슴에서 목 뿌리로 부드럽게 좁아지는 연속 표면. 목을 숙여도 가슴과 분리된 기둥처럼 보이지 않도록 변형 여유 확보 | 기본 서기·먹기·고개 돌리기 |
| GEO-03 | 머리 | 둥근 정수리와 볼, 완만한 뒤통수. 눈과 부리 주변에 별도의 형태를 조형 | 얼굴 정면·측면 확대 |
| GEO-04 | 날개 뿌리 | 등 상부의 어깨에서 시작해 옆구리를 감싸도록 배치. 어깨 주변 깃이 뿌리 경계를 덮음 | 위·옆·뒤와 날개 펼친 자세 |
| GEO-05 | 접힌 날개 | 몸통에 밀착하면서도 자체 두께와 층을 유지. 앞쪽 어깨는 도톰하고 뒤쪽 긴깃으로 갈수록 얇아짐 | 측면·후면 45° 확대 |
| GEO-06 | 꼬리 | 엉덩이 뒤에서 이어지는 겹친 꼬리깃. 기본 자세의 폭·길이·하향 각도는 R01 기준 | 측면·후면·하이 앵글 |

| GEO-08 | 납막·부리 | 부리 위의 흰 납막은 콧등에 밀착된 부드러운 형태. 짧은 위·아래 부리와 끝의 곡률을 구분 | 얼굴 측면·먹기 자세 |
| GEO-09 | 다리·발 | 배 아래로 드러나는 짧은 다리, 분홍·산호색 발, 앞 세 발가락과 뒤 한 발가락, 작은 발톱 | 정면·측면·로우 앵글 |
| GEO-10 | 눈꺼풀 | 열린 눈의 형태를 유지하면서 눈을 덮을 수 있는 메시 또는 모프. 감은 자세에서 안구가 드러나지 않음 | 휴식 자세 확대 |

머리·눈·부리·발은 별도 수정 가능한 구조로 유지한다. 몸통·목이 시각적으로 이어진다는 요구는 모든 부위를 단일 메시로 합치라는 의미는 아니다. 최종 화면에서의 연결과 변형 품질을 기준으로 판단한다.

## 6. 깃털의 구조·방향·밀도

### 6.1 표현 단위

- **실루엣과 겹침을 만드는 깃**: 날개 덮깃, 긴 날깃, 꼬리깃, 목의 주요 겹깃은 형상으로 표현한다.
- **미세한 결**: 깃털 안의 가는 결, 머리·가슴의 작은 잔깃은 노멀·거칠기 맵과 필요한 최소 형상을 조합한다.
- 기본 관찰 거리와 얼굴 확대 거리 모두에서 확인한다. 깃마다 간격·폭·회전을 조금씩 달리하되 주된 흐름은 유지한다.

### 6.2 부위별 규칙

| ID | 부위 | 깃털 흐름과 크기 | 품질 기준 |
|---|---|---|---|
| FEA-01 | 머리·볼 | 짧고 조밀하며 머리 곡면을 따라 목 쪽으로 이어짐 | 정수리 실루엣이 과도하게 가시처럼 솟지 않고 확대에서 잔결이 보임 |
| FEA-02 | 목 | 턱 아래·뒷목에서 가슴·등 쪽으로 흐르는 작은 겹깃. 부위 경계를 따라 방향을 연속적으로 변경 | 깃 뿌리는 가려지고 끝부분과 미세한 틈이 읽힘 |
| FEA-03 | 가슴·배 | 목보다 부드럽고 촘촘함. 가슴 곡면에서 배와 뒤쪽으로 이어지는 흐름 | 낮은 대비의 작은 요철과 부드러운 외곽 유지 |
| FEA-04 | 어깨·등 | 목 뒤에서 등·날개 뿌리 방향으로 연결. 어깨 깃이 몸통과 날개의 접합부를 덮음 | 날개 앞쪽에 노출된 구멍·절단선이 없음 |
| FEA-05 | 날개 덮깃 | 작은 덮깃 → 중간 덮깃 → 큰 덮깃 순으로 크기와 층을 구분. 둥근 깃 끝이 뒤·바깥쪽으로 포개짐 | 위층이 다음 층의 뿌리를 가리고, R01처럼 넓은 깃면이 읽힘 |
| FEA-06 | 날깃 | 어깨·팔·손목 구조를 따라 긴깃 배열. 접으면 뒤쪽으로 포개지고 펴면 부채꼴로 벌어짐 | 접기와 펼치기 모두에서 깃 순서·끝 방향 유지 |
| FEA-07 | 꼬리깃 | 중심선에서 좌우로 겹침과 벌어짐을 조정. 날개 끝과 꼬리를 구분 | 후면에서 좌우 배열과 층이 읽힘 |

### 6.3 날개 겹침의 제작 규칙

1. 뼈와 날개 외곽을 먼저 정하고, 긴 날깃과 덮깃을 그 구조에 맞춰 배치한다.
2. 덮깃은 원형 판을 옆구리에 붙인 형태가 아니라 날개 곡률을 따라 눕는 얇고 완만하게 휜 형태로 만든다.
3. 깃의 뿌리와 끝을 구분하고, 겹침 순서가 뒤집히지 않게 한다. 길이·폭·겹침 간격은 같은 층 안에서 연속적으로 변한다.
4. 검은 두 줄 무늬는 개별 깃의 UV·색 마스크와 연결한다. 깃 끝의 경계를 따라 무늬가 끊기고 이어져야 한다.
5. 접힌 상태에서는 몸통 밀착과 층 두께를, 펼친 상태에서는 어깨 연결·긴깃의 방사 방향·날개 아래쪽을 함께 확인한다.
6. 깃 수는 시트의 화면상 개수를 기계적으로 복사하지 않는다. 근접 관찰에서 읽히는 밀도와 웹 성능을 함께 확인해 결정한다.

## 8. 리그·기본 자세 명세

### 8.1 리그 구성

최소 제어 부위는 루트·골반·가슴·목·머리·좌우 어깨/팔/손목·꼬리·좌우 다리/발·눈꺼풀이다. 깃털은 부위에 맞는 본·스킨 또는 묶음 제어를 사용한다. 원본의 제약·드라이버 결과는 내보낼 때 필요한 데이터로 베이크한다.

리깅 전에 좌표·스케일을 정리하고, 내보낸 GLB를 다시 불러와 본 계층·바인드 포즈·노멀·깃 변형을 확인한다. 이후의 형상 수정에는 스킨 가중치와 자세 회귀 확인을 포함한다.

### 8.2 기본 자세

| ID | 자세 | 주요 제어 | 완료 기준 |
|---|---|---|---|
| POSE-01 / `stand` | 기본 서기 | 루트·가슴·목·양발 | 양발 접지, 좌우 무게 균형, R01 기본 체형 유지 |
| POSE-02 / `step` | 한 발 들기 | 골반·무게 이동·다리·발가락 | 지지발이 바닥에 남고 들린 발의 관절이 자연스러움 |
| POSE-03 / `peck` | 먹기 | 몸통 기울임·목·머리·부리 | 부리 끝이 바닥 가까이 오고 목·가슴 표면이 이어짐. 머리가 몸을 관통하지 않음 |
| POSE-04 / `alert` | 고개 돌리기 | 목·머리 회전 | 시선이 바뀌어도 목 부피와 깃 방향이 유지됨 |
| POSE-05 / `spread` | 날개 펼치기 | 어깨·팔꿈치·손목·깃·꼬리 | 몸통에 연결된 동일 날개가 펼쳐지고 긴깃이 부채꼴로 정렬됨 |
| POSE-06 / `crouch` | 앉기·웅크리기 | 골반 높이·다리 접기·몸통 변형 | 배가 낮아지고 다리가 가려지지만 몸 전체가 단순히 찌그러지지 않음 |
| POSE-07 / `rest` | 눈 감고 휴식 | 눈꺼풀·목·몸통 | 눈이 실제로 덮이고 깃과 체형이 안정적으로 유지됨 |

모든 자세는 같은 모델에 적용한다. 정지 자세를 짧은 glTF 클립 또는 저장된 본·모프 값으로 전달하는 방식은 도구 검증 후 정하되, 매핑·기준 시점·전환 방법을 manifest에 기록한다. 1차 자세 선택 시 갑작스러운 루트 이동이나 모델 교체가 발생하지 않아야 한다.

## 9. 웹 관찰 화면과 성능

### 9.1 관찰 화면

- `/pigeon`에서 모델 1개체를 표시한다. 기본 배경은 밝은 무채색, 바닥은 접지를 확인할 수 있는 단순한 면으로 한다.
- 기능: 마우스 회전·확대, 8방향 고정 시점, 기본 자세 선택, 무채색/최종 재질 보기, 기본 자세·카메라로 초기화, 홈 복귀.
- 얼굴·목·날개·발을 확대할 수 있도록 최소·최대 거리와 카메라 타깃을 조정한다.
- 로딩 중·파일 오류·그래픽 초기화 실패는 구분해 표시한다. 페이지 이탈 시 로딩을 취소하고 GPU·이벤트·애니메이션 자원을 정리한다.
- 모델 파일명·해시·세부 통계는 개발 검증 기록에 보관한다. 관찰 화면의 문구는 사용자에게 필요한 시점·자세·상태를 중심으로 구성한다.
- 푸딩과 홈의 기존 기능에 영향을 주지 않도록 모델·장면은 비둘기 페이지에서 지연 로딩한다.

### 9.2 초기 성능 설계값

아래 수치는 제작 시작용 예산이다. 검증 PC가 지정되지 않았으며 달성한 수치가 아니다. 모델 품질과 실제 측정 결과를 함께 보고 조정 내역을 기록한다.

## 10. 단계별 실행·완료 기준

각 단계의 완료는 작업자가 실제 결과를 보고 판정한다. 차이가 남으면 해당 단계에서 수정하며, 단계마다 사용자 확인을 필수로 요구하지 않는다.

| 단계 | 작업·산출물 | 다음 단계로 넘어가는 기준 |
|---|---|---|
| 1 | R01 구역 정리, 비율 측정표, 좌우·카메라 규칙 | 기본 3방향의 공통 체형 기준과 미확정 항목 기록 |
| 2 | 날개 샘플 생성, GLB 재가져오기·웹 표시 시험 | 사용할 Blender·도구 버전과 내보내기 경로 확인. 도입 실패 시 직접 제작 경로로 전환 |
| 3 | 몸통·목·머리의 무채색 모델, 8방향 캡처 | GEO-01~03의 비율·연결 확인. 색·조명으로 가린 체형 문제 없음 |
| 4 | 얼굴·발 제작, 확대 캡처 | GEO-07~10과 접지 확인 |
| 5 | 날개 뿌리·덮깃·날깃·꼬리, 접힘/펼침 캡처 | GEO-04~06, FEA-04~07의 부착·층·깃 방향 확인 |
| 6 | 머리·목·가슴·배 깃털, 부위 확대 | FEA-01~03 및 부위 사이 흐름·밀도 확인 |
| 7 | 색·노멀·거칠기·목 광택, 최종 재질 8방향 | MAT-01~06을 중립광에서 확인하고 Blender/웹 차이 기록 |

첫 제작 구간은 **1~3단계**다. 이 구간의 산출물은 참고 기준과 도구 시험 결과, 무채색 체형 비교이며 최종 깃털·재질 모델 완료로 표시하지 않는다.

## 11. 검증과 최종 완료 판정

### 11.1 기술 검증

- GLB를 새로 불러와 메시·재질·텍스처·본·포즈가 누락되지 않는지 확인한다.
- 현재 자산 버전과 원본 해시가 manifest·캡처 기록과 일치하는지 확인한다.
- `/pigeon` 직접 진입·새로고침·시점/자세 전환·초기화·홈 복귀를 확인한다.
- 손상 파일·로딩 중 이탈·반복 진입에서 오류 처리와 자원 해제를 확인한다.
- 홈·푸딩의 기존 검사, 프로젝트 빌드와 푸딩 원본 일치 검사를 변경 범위에 맞춰 수행한다.
- 화면 예외·그래픽 오류·재질 누락·성능을 기록한다. 자동 검사는 로딩·데이터·회귀 확인에 사용한다.

### 11.2 외형 검증

기술 검증 통과와 외형 완성을 별도로 판정한다. 실제 웹 캡처를 R01과 나란히 놓고 다음을 확인한다.

| 관찰 영역 | 필수 확인 내용 |
|---|---|
| 전체 8방향 | 동일한 체형·눈·부리·발·날개가 모든 시점에서 유지됨 |
| 정면 | 머리 대비 몸통 폭, 짧은 목, 가슴·배의 볼륨, 양발 간격 |
| 측면 | 머리-목-가슴 연결, 배 높이, 접힌 날개 길이·두께, 꼬리와 발 위치 |
| 후면·위쪽 | 어깨와 등 연결, 양 날개 겹침, 꼬리 뿌리·중심선 |
| 얼굴 확대 | 홍채·동공·눈테·납막의 비율과 머리의 짧은 잔깃 |
| 목 확대 | 겹깃의 방향·끝·밀도와 국소적인 녹색·보라색 광택 |
| 날개 확대 | 뿌리의 가려짐, 덮깃 층, 깃 끝의 겹침, 두 줄 무늬의 연결 |
| 자세 7종 | 같은 모델의 관절 변화로 표현되며 목·날개·발에 큰 관통이나 형태 붕괴가 없음 |

체형은 동일한 높이·바닥선으로 정렬한 무채색 비교와 실루엣 겹침으로 먼저 확인한다. 렌즈·원근 차이를 기록하고, 정렬 과정에서 비등방 스케일로 모델의 폭·높이를 임의 보정하지 않는다. 잔깃은 확대 캡처와 실제 관찰 거리 모두에서 확인한다.

### 11.3 비교 기록 형식

검증마다 다음을 남긴다.

- 검증일, 모델 revision, 원본·GLB 해시, 도구 버전과 검증 환경
- R01 구역 ID, 카메라·광원·포즈·재질 모드와 실제 캡처 경로
- 요구사항 ID, 관찰한 차이, 원인 추정, 수정 내용, 재검증 결과
- 통과·미통과·미검증 상태와 남은 차이

최소 캡처 세트는 **최종 재질 8방향**, **무채색 정면·측면·후면**, **얼굴 정면·측면 및 목·날개 뿌리/겹깃·발 확대**, **기본 자세 7종**이다. 모이 먹기 측면·날개 펼치기 전면·앉기 정면을 포함한다. 캡처는 실제 3D 장면에서 생성하고, 생성 이미지나 참고 시트를 결과물로 대신 제출하지 않는다.

### 11.4 1차 완료 체크리스트

- [ ] 수정 가능한 Blender 원본과 모든 텍스처·출처가 보관되어 있다.
- [ ] 몸통·목·머리의 체형과 연결을 무채색 8방향에서 확인했다.
- [ ] 날개 뿌리, 덮깃의 층, 긴깃·꼬리의 겹침을 확인했다.
- [ ] 얼굴·목·몸통 깃의 크기·방향·밀도를 확대에서 확인했다.

## 12. 현재 상태와 다음 작업

현재 `/pigeon`은 기존 렌더링을 제거한 준비 화면이다. 이 명세서 작성 시점에 새 메시·텍스처·리그·GLB·검증 캡처는 생성하지 않았다. 참고 이미지 파일의 저장소 보관, 비율 실측, 사용 도구의 실행 검증과 검증 PC 지정은 구현 시 처리할 항목이다.
